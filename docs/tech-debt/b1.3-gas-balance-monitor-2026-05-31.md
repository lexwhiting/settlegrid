## What + why
The gas wallet pays for every on-chain settlement (circle-nano + x402). If it runs dry, settlements fail (`submit-error GAS_WALLET_INSUFFICIENT`) and rows freeze `pending`. B1.3 adds a cron that reads the wallet's Base-mainnet ETH balance every 6h and emails an alert when low (the `gasWalletLowEmail` template already existed).

## What shipped
- `apps/web/src/app/api/cron/gas-balance-check/route.ts` — the cron GET handler (cron-secret auth → read balance → classify → email if low). Registered `0 */6 * * *` in `apps/web/vercel.json`.
- `apps/web/src/lib/settlement/gas-wallet-monitor.ts` — pure `classifyGasBalance` (WARN `<0.004`, CRITICAL `<0.0015` ETH; fails SAFE: unparseable → critical) + I/O `readGasWalletBalanceEth` (viem `getBalance`, dedicated RPC or public fallback).
- `apps/web/src/lib/settlement/circle-nano/settle-engine.ts` — NEW exported `getGasWalletAddress()`, reusing the private `getGasWallet()` key normalization so the monitor reads the SAME address the settler signs from (no key exposure).

### Design choices
- **Mainnet-only.** Base Sepolia is testnet (free gas) — not a settlement-freeze risk; intentionally not monitored.
- **Pure classifier + I/O seam.** The bug-prone threshold logic is pure + unit-tested; the viem read is a separately-mockable seam so the cron handler test proves the alert actually fires.
- **`ADMIN_EMAIL` default = `lexwhiting@gmail.com`** (founder-specified); overridable via the env var.
- **Fail-loud on send failure (intentional divergence).** A `sendEmail` failure throws → 500 → the cron run shows failed. For an ALERT cron a lost send should be visible (unlike monitor-github-issues, which swallows send errors for its less-critical content). Deliberate.
